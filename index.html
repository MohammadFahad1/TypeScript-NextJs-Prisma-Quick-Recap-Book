৪. npm কী?

npm হলো প্যাকেজ ম্যানেজার। অন্যের লেখা লাইব্রেরি তোমার প্রজেক্টে এনে দেয়। package.json ফাইলে প্রজেক্টের নাম, স্ক্রিপ্ট আর নির্ভরতার তালিকা থাকে।

bash
npm install zod            # একটা প্যাকেজ যোগ করো (dependencies-এ)
npm install -D typescript  # -D = শুধু ডেভেলপমেন্টে লাগবে (devDependencies)
npm run dev                # package.json-এর "dev" স্ক্রিপ্ট চালাও
npx create-next-app@latest # npx = ইনস্টল না করেই একটা টুল চালাও
জেনে রাখোnode_modules ফোল্ডার অনেক বড়। এটা কখনো Git-এ তোলা হয় না, আর হারিয়ে গেলে npm install দিলেই ফিরে আসে।

৫. Git বেসিক

Git হলো তোমার কোডের টাইম-মেশিন। প্রতিটা ধাপ সেভ করে রাখে, ভুল করলে পিছনে ফেরা যায়। ডিপ্লয় করার সময়ও লাগবে।

bash

git add .                     # সব পরিবর্তন স্টেজে রাখো
git commit -m "প্রথম কমিট"     # একটা সেভ পয়েন্ট বানাও
git status                    # কী কী বদলেছে দেখো
সতর্কতা.env ফাইলে পাসওয়ার্ড আর ডাটাবেস লিংক থাকে। এটা কখনো GitHub-এ তুলো না। .gitignore ফাইলে .env লেখা আছে কিনা নিশ্চিত করো (Next.js প্রজেক্টে ডিফল্টে থাকে)।

Promise ও async/await

ডাটাবেস বা নেটওয়ার্কের কাজে সময় লাগে, তাই এগুলো "পরে শেষ হবে" এমন কাজ। JavaScript এই কাজের জন্য Promise দেয়, আর async/await দিয়ে সেটা সাধারণ কোডের মতো করে লেখা যায়।

js
async function getUser(id) {
  try {
    const res = await fetch(`https://jsonplaceholder.typicode.com/users/${id}`);
    if (!res.ok) throw new Error("ইউজার পাওয়া যায়নি");
    return await res.json();
  } catch (err) {
    console.error(err.message);
    return null;
  }
}

// একসাথে একাধিক কাজ চালানো
const [a, b] = await Promise.all([getUser(1), getUser(2)]);
সতর্কতাawait ভুলে গেলে তুমি আসল ডাটার বদলে একটা Promise পাবে। Prisma-তে এই ভুল খুব হয়, কারণ প্রতিটা Prisma কুয়েরি async।

Generics (জেনেরিক্স)

ধরো তুমি এমন একটা ফাংশন লিখতে চাও যেটা যেকোনো টাইপের array-র প্রথম আইটেম ফেরত দেয়। any দিলে টাইপ হারিয়ে যায়। জেনেরিক্স হলো টাইপের জন্য "ভেরিয়েবল": ফাংশন কল হওয়ার সময় টাইপ ঠিক হয়।

ts
// ❌ any: ফেরত আসা মানের টাইপ হারিয়ে গেল
function firstAny(arr: any[]): any { return arr[0]; }

// ✅ generic: T হলো টাইপ-ভেরিয়েবল
function first<T>(arr: T[]): T | undefined {
  return arr[0];
}

const a = first([1, 2, 3]);        // a: number | undefined
const b = first(["x", "y"]);       // b: string | undefined

Utility Types, keyof, typeof ও Mapped Types

একই টাইপের সামান্য বদলানো সংস্করণ বারবার হাতে লেখা অপ্রয়োজনীয়। TypeScript-এর বানানো ইউটিলিটি দিয়ে একটা টাইপ থেকে আরেকটা বানানো যায়। Prisma ও Next.js-এ এগুলো খুব কাজে লাগে।

type F = Record<"a" | "b", number>;        // { a: number; b: number }

class Account {
  readonly id: number;
  private balance: number;       // শুধু class-এর ভেতর থেকে ব্যবহার করা যাবে

function useLocalStorage<T>(key: string, initial: T) {
  const [value, setValue] = useState<T>(() => {
    const raw = localStorage.getItem(key);
    return raw ? (JSON.parse(raw) as T) : initial;
  });
  return [value, setValue] as const;
}

Server Component (ডিফল্ট)

App Router-এ প্রতিটা কম্পোনেন্ট ডিফল্টে Server Component। এটা শুধু সার্ভারে চলে, ব্রাউজারে তার JavaScript যায় না। ফলে:

  • ব্রাউজারে কম JavaScript, তাই পেজ হালকা ও দ্রুত।
  • async/await সরাসরি কম্পোনেন্টে লেখা যায়।

কিন্তু পারে না: useState, useEffect, onClick-এর মতো ইভেন্ট, ব্রাউজার API (window, localStorage)।

ফাইলের একদম প্রথম লাইনে "use client" লিখলে সেটা Client Component। এটা ব্রাউজারে ইন্টারঅ্যাক্টিভ হয়: state, effect, ইভেন্ট হ্যান্ডলার, ব্রাউজার API সব চলে। (আগে সার্ভারেও একবার HTML বানানো হয়, তারপর ব্রাউজারে "জীবন্ত" হয়।)

type Todo = { id: number; title: string; done: boolean };
const todos: Todo[] = [];   // শুধু শেখার জন্য, মেমরিতে। পরে ডাটাবেস বসাব

export async function GET() {
  return NextResponse.json(todos);
}

export async function POST(request: Request) {
  const body = await request.json();

  if (typeof body.title !== "string" || body.title.trim() === "") {
    return NextResponse.json({ error: "title আবশ্যক" }, { status: 400 });
  }

  const todo: Todo = { id: Date.now(), title: body.title.trim(), done: false };
  todos.push(todo);
  return NextResponse.json(todo, { status: 201 });
}

    <form action={formAction}>
      <input name="email" type="email" />
      {state.errors?.email && <p style={{ color: "crimson" }}>{state.errors.email}</p>}
      <button disabled={pending}>{pending ? "পাঠানো হচ্ছে…" : "নিবন্ধন"}</button>
      {state.message && <p>{state.message}</p>}
    </form>
  );
}
  • state: অ্যাকশনের সর্বশেষ ফলাফল
  • formAction: ফর্মের action-এ বসাও
  • pending: জমা চলছে কিনা (বাটন বন্ধ রাখতে)

revalidatePath কেন লাগে?

ডাটা বদলানোর পর যে পেজ সেই ডাটা দেখাচ্ছে সেটা নতুন করে তৈরি করতে হয়, নইলে পুরনো ডাটা দেখাবে। revalidatePath("/posts") সেই কাজটা করে।

সতর্কতাServer Action একটা সাধারণ পাবলিক HTTP এন্ডপয়েন্ট। ফাংশনের ভেতরে অবশ্যই (১) ইউজার লগইন করা কিনা, (২) তার অনুমতি আছে কিনা, (৩) ইনপুট ঠিক কিনা যাচাই করো। "UI-তে বাটন লুকানো" কোনো নিরাপত্তা নয়।
সাধারণ ভুলফর্মের <input>-এ name অ্যাট্রিবিউট ভুলে গেলে formData.get("email") সবসময় null দেয়।
নিজে করে দেখোএকটা গেস্টবুক ফর্ম বানাও যেটা useActionState দিয়ে খালি বার্তার জন্য এরর দেখায় আর সফল হলে "ধন্যবাদ" বলে। বাটনে pending অবস্থা দেখাও (অ্যাকশনে await new Promise(r => setTimeout(r, 1500)) বসিয়ে ধীর করো)।

Proxy (ঐতিহাসিকভাবে Middleware)

Proxy হলো একটা ফাংশন যা রিকোয়েস্ট পেজে পৌঁছানোর আগে চলে। এখানে রিডাইরেক্ট, রিরাইট, হেডার বদলানো, সাধারণ লগইন-চেক করা যায়।

সতর্কতাNext.js ১৬-তে এই ফাইলের নাম middleware.ts থেকে বদলে proxy.ts হয়েছে, আর ফাংশনের নামও proxy। পুরনো টিউটোরিয়ালে middleware.ts দেখলে বুঝবে এটা একই জিনিস, শুধু আগের নাম। মাইগ্রেট করতে: npx @next/codemod@canary middleware-to-proxy .
src/proxy.ts
import { NextResponse } from "next/server";
import type { NextRequest } from "next/server";

export function proxy(request: NextRequest) {
  const session = request.cookies.get("session")?.value;
  const { pathname } = request.nextUrl;

  // লগইন ছাড়া /dashboard-এ ঢুকতে চাইলে লগইনে পাঠাও
  if (pathname.startsWith("/dashboard") && !session) {
    return NextResponse.redirect(new URL("/login", request.url));
  }
  return NextResponse.next();
}

// কোন পাথে চলবে। না দিলে সব রিকোয়েস্টে (স্ট্যাটিক ফাইলসহ) চলে
export const config = {
  matcher: ["/dashboard/:path*"],
};

ফাইলটা app ফোল্ডারের পাশে থাকবে (src ব্যবহার করলে src/proxy.ts)।

সতর্কতাProxy-তে শুধু "কুকি আছে কিনা" দেখে পেজ আটকানো একটা সুবিধাজনক প্রথম স্তর, পূর্ণ নিরাপত্তা নয়। আসল অনুমতি যাচাই ডাটা যেখানে আনা হয় (Server Component, Server Action, Route Handler) সেখানেও করতে হবে। Proxy-তে ভারী কাজ বা সরাসরি ডাটাবেস কুয়েরি রেখো না।
নিজে করে দেখোএকটা theme কুকি সেট করার Server Action বানাও (বাটন চাপলে dark/light)। layout-এ cookies() পড়ে <body className={theme}> বসাও। এরপর proxy.ts বানিয়ে /dashboard কুকি ছাড়া খুললে /login-এ পাঠাও।

কেন ক্যাশ?

ডাটাবেস কুয়েরি আর রেন্ডারিং খরচের কাজ। যে ডাটা প্রায় বদলায় না (ব্লগ পোস্ট) সেটা একবার বানিয়ে জমিয়ে রাখলে হাজার ইউজারকে একই ফল দ্রুত দেওয়া যায়।

কিছু নিয়ম (আধুনিক Next.js)

  • Next.js ১৫ থেকে fetch আর GET Route Handler ডিফল্টে ক্যাশ হয় না। তুমি চাইলে ক্যাশ চালু করবে।
  • Next.js ১৬-তে ক্যাশিংয়ের নতুন মডেল আছে: Cache Components। next.config.ts-এ cacheComponents: true দিলে "use cache" ডিরেক্টিভ দিয়ে ফাংশন বা কম্পোনেন্ট স্পষ্টভাবে ক্যাশ করা হয়। অর্থাৎ ক্যাশ হবে তখনই, যখন তুমি বলবে।

import { cacheLife } from "next/cache";

export async function getPosts() {
  "use cache";                 // এই ফাংশনের ফল ক্যাশ হবে

  return prisma.post.findMany();
}

রিলেশনাল (SQL): ডাটা থাকে এক্সেল শিটের মতো টেবিলে। প্রতিটা টেবিলের নির্দিষ্ট কলাম আছে, আর টেবিলগুলো একে অপরের সাথে সম্পর্কিত (relation)। উদাহরণ: PostgreSQL, MySQL।

ডকুমেন্ট (NoSQL): ডাটা থাকে JSON-সদৃশ ডকুমেন্টে, সেগুলো জমা থাকে collection-এ। প্রতিটা ডকুমেন্টের গড়ন আলাদা হতে পারে। উদাহরণ: MongoDB।

বিষয়PostgreSQLMongoDB
ডাটার গড়নটেবিল, সারি (row), কলামcollection, ডকুমেন্ট, ফিল্ড
স্কিমাকড়া (আগে ঠিক করতে হয়)নমনীয় (Prisma তবু নিয়ম বসায়)
সম্পর্কforeign key, JOINরেফারেন্স বা এম্বেড করা ডকুমেন্ট
ট্রানজ্যাকশনখুব শক্তিশালীআছে (replica set লাগে)
ভালো কোথায়অর্থ, অর্ডার, জটিল সম্পর্কযুক্ত ডাটানমনীয় গড়নের ডাটা, দ্রুত পরিবর্তনশীল মডেল

ORM কী এবং Prisma কেন?

ডাটাবেসের সাথে কথা বলতে SQL স্ট্রিং লিখলে ভুল হলে রানটাইমে ধরা পড়ে, টাইপ থাকে না। ORM (Object-Relational Mapper) ডাটাবেসের টেবিলকে কোডের object-এর মতো ব্যবহার করতে দেয়। Prisma এ কাজ করে এভাবে:

  1. তুমি schema.prisma ফাইলে মডেল লেখো।
  2. Prisma সেই মডেল থেকে ডাটাবেস টেবিল (বা collection) আর TypeScript টাইপ বানায়।
  3. তুমি prisma.user.findMany()-এর মতো টাইপ-সেফ কোড লেখো, ভুল করলে এডিটরেই ধরা পড়ে।

PostgreSQL ও MongoDB চালু করা

ডাটাবেস চালানোর দুটো পথ: নিজের কম্পিউটারে (Docker) অথবা ক্লাউডে ফ্রি প্ল্যানে। ক্লাউড সবচেয়ে সহজ, কারণ কিছু ইনস্টল লাগে না।

PostgreSQL: বিকল্প ১ (ক্লাউড)

Neon (neon.com) বা Supabase-এর মতো সার্ভিসে ফ্রি অ্যাকাউন্টে একটা প্রজেক্ট বানালে তারা একটা connection string দেয়। সেটা কপি করে .env-এ রাখো।

MongoDB: বিকল্প ১ (Atlas, সহজতম)

.env
DATABASE_URL="mongodb://localhost:27017/blog?replicaSet=rs0&directConnection=true"

SQL ক্র্যাশ কোর্স

Prisma বেশিরভাগ কাজ করে দেবে, তবু SQL-এর মূল ধারণা জানা থাকলে Prisma-র আচরণ বোঝা সহজ হয় আর সমস্যা ধরা যায়। তাই আধঘণ্টা ব্যয় করো। (এটা PostgreSQL/SQL শেখার পাঠ, MongoDB-র ধারণা ৫ম মডিউলে।)

টেবিল তৈরি

sql
CREATE TABLE users (
  id SERIAL PRIMARY KEY,                 -- অনন্য পরিচয়, নিজে নিজে বাড়ে
  email TEXT NOT NULL UNIQUE,            -- ফাঁকা চলবে না, ডুপ্লিকেট চলবে না
  name TEXT,
  created_at TIMESTAMP DEFAULT NOW()
);

CREATE TABLE posts (
  id SERIAL PRIMARY KEY,
  title TEXT NOT NULL,
  published BOOLEAN DEFAULT false,
  author_id INTEGER NOT NULL REFERENCES users(id)   -- foreign key: users টেবিলের সাথে সম্পর্ক
);
  • Primary key: প্রতিটা সারির অনন্য পরিচয়।
  • Foreign key: অন্য টেবিলের primary key-র দিকে নির্দেশ করে সম্পর্ক বানায়। author_id একটা বৈধ users.id না হলে ডাটাবেস ঢুকতেই দেয় না।

CRUD

sql
-- Create
INSERT INTO users (email, name) VALUES ('rina@example.com', 'রিনা');

-- Read
SELECT * FROM users;
SELECT id, name FROM users WHERE email = 'rina@example.com';
SELECT * FROM posts WHERE published = true ORDER BY id DESC LIMIT 10 OFFSET 0;

-- Update
UPDATE users SET name = 'রিনা আক্তার' WHERE id = 1;

-- Delete
DELETE FROM posts WHERE id = 5;
সতর্কতাUPDATE বা DELETE-এ WHERE ভুলে গেলে পুরো টেবিলের সব সারি বদলে বা মুছে যায়। সবসময় আগে SELECT দিয়ে দেখে নাও কোন সারিগুলো ধরা পড়বে।

ফিল্টার

sql
SELECT * FROM posts WHERE title LIKE '%Next%';           -- যেকোনো জায়গায় মিল
SELECT * FROM posts WHERE id IN (1, 2, 3);
SELECT * FROM users WHERE created_at > '2026-01-01' AND name IS NOT NULL;

JOIN: দুই টেবিল জোড়া লাগানো

sql
SELECT posts.title, users.name AS author
FROM posts
JOIN users ON posts.author_id = users.id;

Prisma-তে include: { author: true } লিখলে আসলে এরকম JOIN-ই চলে।

সম্পর্কের ধরন

ধরনউদাহরণকীভাবে
এক-থেকে-এক (1-1)ইউজার ↔ প্রোফাইলforeign key-তে UNIQUE
এক-থেকে-অনেক (1-n)ইউজার → অনেক পোস্টঅনেক-দিকের টেবিলে foreign key
অনেক-থেকে-অনেক (m-n)পোস্ট ↔ ট্যাগমাঝে একটা জোড়া টেবিল

aggregate ও GROUP BY

sql
SELECT COUNT(*) FROM posts;
SELECT author_id, COUNT(*) AS total FROM posts GROUP BY author_id;
SELECT AVG(price), MAX(price) FROM products;

index

বই-এর সূচির মতো। কোনো কলামে বারবার খোঁজ চালালে index দিলে সার্চ অনেক দ্রুত হয়, তবে লেখার সময় সামান্য বেশি খরচ হয়।

sql
CREATE INDEX idx_posts_author ON posts(author_id);

transaction

একাধিক কাজ "হয় সব হবে, নয় কিছুই না"। যেমন ব্যাংকে এক অ্যাকাউন্ট থেকে টাকা কাটা আর অন্যটায় জমা, দুটো একসাথে সফল হতে হবে।

sql
BEGIN;
UPDATE accounts SET balance = balance - 500 WHERE id = 1;
UPDATE accounts SET balance = balance + 500 WHERE id = 2;
COMMIT;      -- ভুল হলে ROLLBACK;

SQL injection: কেন সরাসরি স্ট্রিং জোড়া দেওয়া বিপজ্জনক

js
// ❌ ভয়ানক: ইউজার ' OR 1=1 -- পাঠিয়ে সব ডাটা বের করে ফেলতে পারে
db.query("SELECT * FROM users WHERE name = '" + input + "'");

Prisma-র সাধারণ কুয়েরি আপনা থেকেই নিরাপদ (প্যারামিটার ব্যবহার করে)। কাঁচা SQL লিখলে শুধু নিরাপদ পদ্ধতি ব্যবহার করবে (পাঠ ৪.৭)।

নিজে করে দেখোNeon-এর SQL Editor বা psql দিয়ে উপরের দুটো টেবিল বানাও। দুই-তিনজন ইউজার আর কয়েকটা পোস্ট ঢুকিয়ে JOIN দিয়ে "পোস্টের শিরোনাম + লেখকের নাম" বের করো।

Prisma ইনস্টল ও প্রথম সংযোগ

Prisma-র তিনটা অংশ:

  • Prisma Schema (schema.prisma): তোমার ডাটা মডেলের বর্ণনা।
  • Prisma Migrate: schema থেকে ডাটাবেসের টেবিল বানায় ও বদলায়।
  • Prisma Client: schema থেকে স্বয়ংক্রিয়ভাবে বানানো টাইপ-সেফ কোড, যা দিয়ে কুয়েরি লেখো।
জেনে রাখোএই মডিউল Prisma ৭ ধরে লেখা। Prisma ৭-এ আগের ভার্সনের চেয়ে কিছু বড় পরিবর্তন আছে (generator-এর নাম, prisma.config.ts, driver adapter, আউটপুট ফোল্ডার বাধ্যতামূলক)। পুরনো টিউটোরিয়ালের কোড হুবহু না মিললে এটাই কারণ। MongoDB-র জন্য আলাদা মডিউলে Prisma ৬.১৯ ব্যবহার হবে।

ধাপ ১: নতুন Next.js প্রজেক্টে ইনস্টল

আগের মডিউলের মতো create-next-app দিয়ে প্রজেক্ট (src ডিরেক্টরিসহ) বানিয়ে ভেতরে ঢোকো, তারপর:

bash
npm install prisma tsx --save-dev
npm install @prisma/client @prisma/adapter-pg dotenv
npx prisma init --datasource-provider postgresql --output ../src/generated/prisma
  • prisma: CLI টুল (ডেভেলপমেন্টে)
  • @prisma/client: কুয়েরি করার লাইব্রেরি
  • @prisma/adapter-pg: PostgreSQL-এর জন্য driver adapter (Prisma ৭-এ বাধ্যতামূলক)
  • tsx: TypeScript ফাইল সরাসরি চালাতে (seed স্ক্রিপ্টের জন্য)

init চালালে তৈরি হয়: prisma/schema.prisma, prisma.config.ts আর .env (যেখানে DATABASE_URL বসাবে)।

ধাপ ২: schema.prisma

prisma/schema.prisma

  provider = "prisma-client"

}

});

id কেমন হবে?

export async function searchPosts(q: string, page = 1, pageSize = 10) {
  const where = q
    ? { title: { contains: q, mode: "insensitive" as const }, published: true }
    : { published: true };

}

Relation: সম্পর্ক বানানো ও ব্যবহার

বেশিরভাগ বাস্তব ডাটা সম্পর্কযুক্ত। Prisma-য় relation লেখা সহজ, আর কুয়েরির সময় এক লাইনে সম্পর্কিত ডাটা আনা যায়।

এক-থেকে-অনেক (1-n): User → Posts

prisma
model User {
  id    Int    @id @default(autoincrement())
  email String @unique
  name  String?
  posts Post[]                      // এক ইউজারের অনেক পোস্ট (এটা শুধু Prisma-র দিক, কলাম নয়)
}

model Post {
  id       Int    @id @default(autoincrement())
  title    String
  authorId Int                      // আসল foreign key কলাম
  author   User   @relation(fields: [authorId], references: [id], onDelete: Cascade)
}
  • authorId আসল কলাম, author আর posts হলো relation ফিল্ড (ডাটাবেসে কলাম হয় না, শুধু কুয়েরিতে সুবিধা দেয়)।
  • @relation(fields: [...], references: [...]) বলে দেয় কোন কলাম কোন কলামকে নির্দেশ করে।
  • onDelete: Cascade: ইউজার মুছলে তার সব পোস্টও মুছে যায়। অন্য বিকল্প: Restrict (পোস্ট থাকলে ইউজার মুছতে দেবে না), SetNull (authorId-কে null করবে, তখন authorId Int? হতে হবে)।

  throw e;   // অচেনা এরর আবার ছুঁড়ে দাও
}

MongoDB-র id: সবচেয়ে বড় পার্থক্য

প্রতিটা MongoDB ডকুমেন্টে _id নামে একটা ফিল্ড থাকে, সাধারণত ObjectId (১২ বাইটের অনন্য আইডি, দেখতে ২৪ অক্ষরের hex স্ট্রিং, যেমন "6650f1c2a1b2c3d4e5f60789")। Prisma _ দিয়ে শুরু করা ফিল্ড নাম চায় না, তাই লাইনটা এভাবে লিখি:

prisma
id String @id @default(auto()) @map("_id") @db.ObjectId
  • String: কোডে id হবে string
  • @id: এটাই primary key
  • @default(auto()): MongoDB নিজে ObjectId বানাবে
  • @map("_id"): ডাটাবেসে ফিল্ডের নাম _id
  • @db.ObjectId: ডাটাবেসে টাইপ ObjectId (সাধারণ string নয়)

মডেল, সম্পর্ক ও Embedded Document

রেফারেন্স সম্পর্ক (SQL-এর মতোই)

prisma
model User {
  id    String @id @default(auto()) @map("_id") @db.ObjectId
  email String @unique
  posts Post[]
}

model Post {
  id       String  @id @default(auto()) @map("_id") @db.ObjectId
  title    String
  authorId String  @db.ObjectId           // ← foreign key ও ObjectId টাইপের হতে হবে
  author   User    @relation(fields: [authorId], references: [id], onDelete: Cascade)

  @@index([authorId])                     // সম্পর্কের কলামে index দাও
}

কুয়েরি পুরোপুরি এক: include: { author: true }, posts: { create: [...] }, connect ইত্যাদি।

সতর্কতাMongoDB-তে ডাটাবেস-স্তরের foreign key constraint নেই। Prisma সম্পর্কের নিয়ম (যেমন onDelete: Cascade) নিজে "অনুকরণ" করে (relation mode prisma)। এর মানে: Prisma-র বাইরে (Compass বা অন্য কোডে) ডাটা মুছলে অনাথ (orphan) রেকর্ড পড়ে থাকতে পারে। সব লেখালেখি Prisma দিয়েই করার চেষ্টা করো।

অনেক-থেকে-অনেক (m-n)

MongoDB-তে implicit m-n নেই, আর জোড়া collection-ও সাধারণ নয়। দুই দিকেই id-র array রাখো:

prisma
model Post {
  id     String   @id @default(auto()) @map("_id") @db.ObjectId
  tagIds String[] @db.ObjectId
  tags   Tag[]    @relation(fields: [tagIds], references: [id])
}

model Tag {
  id      String   @id @default(auto()) @map("_id") @db.ObjectId
  name    String   @unique
  postIds String[] @db.ObjectId
  posts   Post[]   @relation(fields: [postIds], references: [id])
}
জেনে রাখোএখানে দুই দিকের id array আলাদা আলাদা, আর connect করলে Prisma দুই দিকেই আপডেট করে। নিজের হাতে একদিক বদলালে অন্যদিক মিলবে না, তাই connect/disconnect ব্যবহার করো।

Embedded document: composite type

MongoDB-র বড় সুবিধা: একটা ডকুমেন্টের ভেতরে আরেকটা গঠন সরাসরি রাখা যায়। আলাদা collection আর JOIN লাগে না। Prisma-য় এর নাম composite type।

prisma
type Address {
  street String
  city   String
  zip    String?
}

type Social {
  platform String
  url      String
}

model User {
  id      String   @id @default(auto()) @map("_id") @db.ObjectId
  email   String   @unique

  socials Social[]          // এম্বেড করা অবজেক্টের array
}

ডাটা সবসময় মূল ডকুমেন্টের সাথেই পড়া হয় (ঠিকানা)ডাটা আলাদা করে পড়া/বদলানো হয়

টিপনিয়ম: "ছোট, মালিকের সাথে অবিচ্ছেদ্য, সীমিত" হলে এম্বেড। "বড়, বাড়তেই থাকবে, অন্য জায়গায়ও লাগে" হলে আলাদা collection ও রেফারেন্স।

src/lib/jwt.ts
import { SignJWT, jwtVerify } from "jose";

const secret = new TextEncoder().encode(process.env.SESSION_SECRET);

export const SESSION_COOKIE = "session";
export const SESSION_DAYS = 7;

export async function signToken(userId: number) {
  return new SignJWT({ userId })
    .setProtectedHeader({ alg: "HS256" })
    .setIssuedAt()
    .setExpirationTime(`${SESSION_DAYS}d`)
    .sign(secret);
}

export async function readSession(token: string | undefined) {
  if (!token) return null;
  try {
    const { payload } = await jwtVerify(token, secret, { algorithms: ["HS256"] });
    return typeof payload.userId === "number" ? { userId: payload.userId } : null;
  } catch {
    return null;   // মেয়াদ শেষ বা জাল টোকেন
  }
}
src/lib/session.ts
import "server-only";
import { cookies } from "next/headers";
import { SESSION_COOKIE, SESSION_DAYS, signToken } from "@/lib/jwt";

export async function createSession(userId: number) {
  const token = await signToken(userId);

  (await cookies()).set(SESSION_COOKIE, token, {
    httpOnly: true,
    secure: process.env.NODE_ENV === "production",
    sameSite: "lax",
    path: "/",
    expires: new Date(Date.now() + SESSION_DAYS * 24 * 60 * 60 * 1000),
  });
}

export async function deleteSession() {
  (await cookies()).delete(SESSION_COOKIE);
}

"use server";

import bcrypt from "bcryptjs";
import { redirect } from "next/navigation";
import { z } from "zod";
import { prisma } from "@/lib/prisma";
import { Prisma } from "@/generated/prisma/client";
import { createSession, deleteSession } from "@/lib/session";
import { LoginSchema, RegisterSchema, type FormState } from "@/lib/validation";

export async function register(_prev: FormState, formData: FormData): Promise<FormState> {
  const parsed = RegisterSchema.safeParse(Object.fromEntries(formData));
  if (!parsed.success) {
    return { errors: z.flattenError(parsed.error).fieldErrors };
  }
  const { name, email, password } = parsed.data;

  const hash = await bcrypt.hash(password, 10);   // 10 = কাজের মাত্রা (cost)

  let userId: number;
  try {
    const user = await prisma.user.create({ data: { name, email, password: hash } });
    userId = user.id;
  } catch (e) {
    if (e instanceof Prisma.PrismaClientKnownRequestError && e.code === "P2002") {
      return { errors: { email: ["এই ইমেইল আগেই নিবন্ধিত"] } };
    }
    console.error("register failed", e);
    return { message: "কিছু একটা ভুল হয়েছে, আবার চেষ্টা করো" };
  }

  await createSession(userId);
  redirect("/dashboard");   // redirect error ছোঁড়ে, তাই try/catch-এর বাইরে রাখতে হয়
}

  }
  const { email, password } = parsed.data;

  const user = await prisma.user.findUnique({ where: { email } });

  if (!user || !ok) return { message: "ইমেইল বা পাসওয়ার্ড ভুল" };

  await createSession(user.id);
  redirect("/dashboard");
}

import { NextResponse, type NextRequest } from "next/server";
import { readSession, SESSION_COOKIE } from "@/lib/jwt";

export async function proxy(request: NextRequest) {
  const token = request.cookies.get(SESSION_COOKIE)?.value;
  const session = await readSession(token);
  const { pathname } = request.nextUrl;

  if (pathname.startsWith("/dashboard") && !session) {
    return NextResponse.redirect(new URL("/login", request.url));
  }
  // লগইন করা ইউজারকে /login ও /register দেখানোর দরকার নেই
  if ((pathname === "/login" || pathname === "/register") && session) {
    return NextResponse.redirect(new URL("/dashboard", request.url));
  }
  return NextResponse.next();
}

export const config = {
  matcher: ["/dashboard/:path*", "/login", "/register"],

import { prisma } from "@/lib/prisma";

const PAGE_SIZE = 6;

export async function getPublishedPosts(q = "", page = 1) {
  const where = {
    published: true,
    ...(q ? { title: { contains: q, mode: "insensitive" as const } } : {}),
  };

  const [items, total] = await Promise.all([
    prisma.post.findMany({
      where,
      orderBy: { createdAt: "desc" },
      skip: (page - 1) * PAGE_SIZE,
      take: PAGE_SIZE,
      select: {
        id: true, title: true, createdAt: true,
        author: { select: { name: true } },
      },
    }),
    prisma.post.count({ where }),
  ]);

  return { items, total, page, totalPages: Math.max(1, Math.ceil(total / PAGE_SIZE)) };
}

function parsePost(formData: FormData) {
  return PostSchema.safeParse({
    title: formData.get("title"),
    content: formData.get("content"),
    published: formData.get("published") === "on",   // চেকবক্স টিক দিলে "on" আসে
  });
}

export async function createPost(_prev: FormState, formData: FormData): Promise<FormState> {
  const { userId } = await verifySession();                 // ১. লগইন আছে?
  const parsed = parsePost(formData);                       // ২. ডাটা ঠিক?
  if (!parsed.success) return { errors: z.flattenError(parsed.error).fieldErrors };

  await prisma.post.create({ data: { ...parsed.data, authorId: userId } });   // ৩. সেভ

  revalidatePath("/");
  revalidatePath("/dashboard");
  redirect("/dashboard");
}

// id আগে থেকে bind করা হবে, তাই প্রথম প্যারামিটার id
export async function updatePost(
  id: number,
  _prev: FormState,
  formData: FormData
): Promise<FormState> {
  const { userId } = await verifySession();
  const parsed = parsePost(formData);
  if (!parsed.success) return { errors: z.flattenError(parsed.error).fieldErrors };

  // where-এ authorId থাকায় শুধু নিজের পোস্টই মিলবে (পাঠ ৬.৪)
  const result = await prisma.post.updateMany({
    where: { id, authorId: userId },
    data: parsed.data,
  });
  if (result.count === 0) return { message: "পোস্ট পাওয়া যায়নি বা তোমার অনুমতি নেই" };

  revalidatePath("/");
  revalidatePath(`/posts/${id}`);
  revalidatePath("/dashboard");
  redirect("/dashboard");
}

export async function deletePost(id: number) {
  const { userId } = await verifySession();
  await prisma.post.deleteMany({ where: { id, authorId: userId } });
  revalidatePath("/");
  revalidatePath("/dashboard");
}

  // খসড়া পোস্ট শুধু লেখক দেখতে পাবে

}

হোমপেজের কুয়েরি আমরা getPublishedPosts-এ রেখেছি, তাই একই ফাংশন দিয়ে JSON API খুব সহজ। মোবাইল অ্যাপ বা অন্য ওয়েবসাইট এটা ব্যবহার করতে পারবে।

src/app/api/posts/route.ts
import { NextResponse } from "next/server";
import { z } from "zod";
import { getPublishedPosts } from "@/lib/queries";

const Query = z.object({
  q: z.string().trim().max(100).default(""),
  page: z.coerce.number().int().min(1).default(1),   // "2" (string) → 2 (number)
});

export async function GET(request: Request) {
  const { searchParams } = new URL(request.url);
  const parsed = Query.safeParse(Object.fromEntries(searchParams));

  if (!parsed.success) {
    return NextResponse.json(
      { error: "ভুল প্যারামিটার", details: z.flattenError(parsed.error).fieldErrors },
      { status: 400 }
    );
  }

  try {
    const data = await getPublishedPosts(parsed.data.q, parsed.data.page);
    return NextResponse.json(data);
  } catch (e) {
    console.error("GET /api/posts failed", e);
    return NextResponse.json({ error: "সার্ভারে সমস্যা হয়েছে" }, { status: 500 });
  }
}
